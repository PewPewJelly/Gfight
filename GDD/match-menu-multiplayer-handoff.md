# 경기 기본 규칙·메인 메뉴·멀티플레이어 구현 핸드오프

## 범위와 근거

첨부 메모의 기본 규칙과 이번 요청의 메인 메뉴·멀티플레이어 환경 요구를 반영한다. **최소 구현 환경은 개발용 한 컴퓨터에서 둘 이상의 독립 플레이어 클라이언트를 실행해 같은 경기에 접속하는 방식으로도 충족할 수 있다.** 외부 네트워크를 통한 접속 지원 여부는 미정이다.

## 확정된 경기 규칙

| 항목 | 요구사항 |
|---|---|
| 승리 | 자신을 제외한 모든 플레이어의 스톡이 없어지면 승리한다. |
| 최소 인원 | 한 경기에 플레이어가 최소 2명 필요하다. |
| 시작 위치 | 플레이어는 서로 다른 곳에서 경기를 시작한다. |

## 구현 범위

### 메인 메뉴와 경기 진입

1. 게임 실행 시 메인 메뉴를 표시한다.
2. 메인 메뉴에서 멀티플레이어 경기 참여 흐름으로 진입할 수 있게 한다. 메뉴의 구체 문구·디자인은 미정이다.
3. 경기 시작 전 현재 참가 플레이어를 구별하고 인원수를 확인할 수 있는 대기 상태를 둔다.
4. 참가 인원이 2명 미만이면 경기 시작을 막는다. 2명 이상이면 경기 시작이 가능하다. 실제 시작 명령의 주체와 방식은 미정이다.

### 멀티플레이어 환경

1. 둘 이상의 플레이어가 **각자 독립적인 입력과 플레이어 상태**로 같은 경기에 참여할 수 있어야 한다.
2. 개발 단계에서는 한 컴퓨터에서 클라이언트를 여러 개 실행해 각 클라이언트를 별도 플레이어로 접속시키는 방식을 허용한다. 이 경우 각 클라이언트가 자신이 조작하는 플레이어를 구별할 수 있어야 한다.
3. 모든 참가자가 같은 경기의 참가 인원, 각 플레이어의 스톡 상태, 경기 시작·종료 및 승리 결과를 일관되게 확인할 수 있어야 한다. 구체 동기화 구조는 사용하는 엔진·네트워크 체계에 맞춰 정한다.

### 경기 시작과 종료

1. 경기 시작 시 각 참가자에게 서로 다른 시작 위치를 배정한다. 위치 좌표와 선정 방식은 미정이다.
2. 각 플레이어의 스톡을 독립적으로 관리한다. 초기 스톡 수, 감소 조건 및 초기화 시점은 미정이다.
3. 어떤 플레이어를 제외한 나머지 모든 플레이어의 스톡이 `0`이 되면 해당 플레이어를 승자로 판정하고 경기 결과를 표시한다.
4. 동시에 여러 명의 스톡이 `0`이 되는 등 승자를 한 명으로 정할 수 없는 경우의 처리는 미정으로 둔다.

## 확인 기준

1. 메인 메뉴에서 멀티플레이어 경기 참여 흐름에 들어갈 수 있다.
2. 한 컴퓨터에서 둘 이상의 독립 클라이언트로 접속하는 개발용 구성 또는 동등한 멀티플레이어 구성이 가능하다.
3. 참가자가 1명이면 경기가 시작되지 않고, 2명 이상이면 시작 가능한 상태가 된다.
4. 경기가 시작되면 플레이어들이 서로 다른 위치에 배치된다.
5. 각 클라이언트는 자신에게 배정된 플레이어만 조작한다.
6. 한 플레이어를 제외한 모든 플레이어의 스톡이 `0`이 되면 그 플레이어가 승자로 표시된다.

## 미정 사항 — 결정이 필요한 내용

| 항목 | 확인할 내용 |
|---|---|
| 접속 범위 | 개발용 한 컴퓨터 다중 클라이언트만 필요한지, 다른 컴퓨터 간 접속까지 필요한지 |
| 경기 생성·시작 | 방 생성/참가 방식, 경기 시작 권한과 시작 입력, 대기 화면 구성 |
| 인원 | 최대 플레이어 수, 경기 중 입장·퇴장·재접속 처리 |
| 스톡 | 초기 스톡 수, 스톡을 잃는 조건, 소진 시 플레이어 처리, 재경기 시 초기화 방식 |
| 승패 예외 | 동시 탈락, 연결 종료, 무승부가 가능한 경우의 결과 |
| 시작 위치 | 좌표, 개수, 배정 순서·무작위 여부, 같은 위치가 배정되지 않도록 할 기준 |
| 메뉴와 결과 화면 | 버튼 문구·구성, 오류 안내, 승리 표시 방식 |
| 동기화·권한 | 경기 상태를 확정하는 주체와 상태 동기화 방식 |

미정 항목에 임시 수치나 게임 규칙을 넣지 않는다. 특히 스톡 감소 조건과 초기 스톡 수가 정해져야 실제 경기 종료까지 이어지는 플레이를 완성할 수 있다.
