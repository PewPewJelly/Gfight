# GDD 전체 구현 현황

## 실행 및 참가

Godot 4.7.2로 `project.godot`을 열고 F5를 누른다. 첫 화면은 메인 메뉴다.
화면 흐름과 대기방은 `Docs/00_System_Context.md`, `Docs/01-start-game-spec.md`, `Docs/02-lobby-spec.md`(2026-10-27 프로토타입)를 따른다.
Docs가 다루지 않는 경기 HUD·결과 화면은 기존 `Design/ui-ux-scenes-v2.pdf` 동작을 그대로 쓴다.

- 같은 프로젝트를 두 번 실행한다. 첫 창: **게임하기 → 실전 → 방 생성**. 두 번째 창: **게임하기 → 실전 → 방 참여** →
  주소 `IP:포트`(처음 값은 이 컴퓨터 IP:27840, 이후 마지막 성공 주소) → **확인**(Enter).
- 대기방에서 참가자가 준비 버튼(빨간 X → 회색 V)을 누르고, 2명 이상 + 참가자 전원 준비이면 호스트의 ▶ 시작 버튼이 켜진다.
- **게임하기 → 훈련장**: 혼자 들어가는 대기방. ▶가 항상 켜져 있고, 경기에 회색 허수아비(목숨 3, 입력 없음)가 함께 나온다.
- 경기: 3초 카운트다운 뒤 A/D 이동, W/S 방향, Space 점프, J 공격, K 스킬로 자기 플레이어만 조작한다. 결과 화면에서 Enter로 확인, 남은 전원이 확인하면 같은 대기방으로 돌아간다.
- 방을 떠나는 길은 대기방 (←) → [나가기]뿐이다. 다른 참가자가 있는 호스트가 나가면 방이 닫히고 참가자는 게임하기 화면 토스트를 본다.
- 로컬 2인(`Session.local_game()`)은 테스트용으로 남아 있고 메뉴 버튼은 없다. P1 WASD + Space/J/K, P2 방향키 + `,`(점프) + `.`(공격) + `/`(스킬).

## 화면 구현 (Docs 00·01·02)

`main.tscn`의 `ScreenRouter`(`scripts/screen_router.gd`)가 화면 하나만 자식으로 두고 바꾼다. 화면은 `enter(data)`로 시작하고
`exit_requested(result)`로 끝난다(Docs/00 §4). 문구와 색은 `scripts/ui_style.gd`, 방·플레이어 데이터는 `scripts/data/`에 있다.

### Docs 기반 프로토타입 임시값·가정 (2026-10-27)

- 해상도: Docs/02 결정 1은 게임 전체 1920×1080이지만 경기장 좌표가 1280×720 기준이라 프로젝트 설정은 그대로 두고, 대기방 무대만 1920×1080으로 그려 창에 맞게 축소했다.
- 메인 메뉴(SYS-00) 명세가 없어 최소 구성만 만들었다.
- 훈련장 허수아비: 플레이어 id 2, 목숨 3, 입력 0, 회색(`UiStyle.DUMMY_COLOR`). 허수아비가 이기면 "허수아비 승리!". 치트 기능(목숨·텔레포트 조절)은 사용자 요청대로 만들지 않았다.
- Docs/00 §3.8의 카탈로그·`MatchSetup` 세부 필드가 없어 `ContentCatalog`(characters, maps), `MatchSetup`(generation, room_mode, map, participants, characters, dummy_ids)로 정했다.
- 닉네임 최대 10자(02 결정 18이 00의 20자보다 우선), 방 이름 12자, 채팅 40자·0.5초 간격, 말풍선 3초.
- 입장·퇴장 알림("P2 님이 들어왔습니다.")은 대기방 토스트로 한 번 보여 준다(호스트가 한 번 보낸 뒤 지움).
- 준비 버튼 아이콘 색은 각 상태의 테두리색과 같게 했다. 뒤로가기 버튼은 흰 바탕·#555 테두리(명세에 색 없음).
- 참가자 카드 말풍선 위치는 명세(아트의 x 74%, y −26%)를 따르되, 맨 위 카드에서 잘리지 않도록 카드 안쪽으로 제한했다.
- 강제 퇴장 후 재입장은 막지 않는다(02 결정 14). 방장 양도·공개/비공개·대기방 카운트다운은 없다(02 §0.3).

### 화면 크기·전체화면

- 기본 실행은 전체화면(`window/size/mode=3`). F11 또는 Alt+Enter로 창 모드 전환(한 컴퓨터에서 두 개 실행할 때).
- 기준 해상도 1280×720, `stretch/mode=canvas_items`, `stretch/aspect=expand`. 16:9가 아닌 화면에서는 레터박스 없이 UI가 화면 가장자리에 붙고,
  경기장은 Camera2D로 화면 가운데에 고정되어 여백만 늘어난다. 여백 색은 배경색(`default_clear_color`)과 같다.
- 장외 판정 영역은 화면 크기와 상관없이 1280×720 기준 그대로다.

### UI·흐름 임시값 ([제안]/[미정])

- 시작 카운트다운 3초(`combat_rules.tres` `start_countdown`), "시작!" 0.7초, 결과 화면 전 정지 0.8초, 페이드 0.2초, 토스트 3초.
- 배율 색: 0% 흰색 → 100% 주황 → 200% 빨강(`UiStyle.DANGER_*`).
- 킬: 장외된 플레이어를 마지막으로 때린 상대에게 1킬. 마지막 공격자 기록은 장외 때 지운다. 자기 낙사·연결 끊김은 킬 없음.
- 준 배율: 내 공격이 실제로 올린 상대 배율의 합.
- 순위: 승자 1위, 나머지는 늦게 탈락한 순. 같은 프레임 탈락은 같은 순위(무승부는 공동 1위, 왕관 없음).
- 결과 화면에서 확인하지 않는 사람은 계속 기다린다(자동 확인 [미정]).
- 랜덤 시작 위치 간 최소 거리는 겹침 방지만 적용한다([미정]).
- 호스트는 준비 집계에서 빠지고 [경기 시작]이 준비를 대신한다.
- 방 가득 참을 알리려고 ENet 서버는 4명 + 거부용 1자리로 연다.
- 버전 비교는 `application/config/version`(0.1.0) 문자열 일치.
- 미구현 [제안]: 장외 섬광·카드 흔들림, 재스폰 직전 위치 표식.

## 미정 항목의 임시 구현 정책

다음은 테스트 가능한 구현을 위한 기본값이며 게임 규칙 확정이 아니다.
디자인 변경 시 Resource와 해당 정책을 함께 갱신한다.

### 이동·플랫폼

`resources/movement_settings.tres`에서 이동 260px/s, 가속·감속 1600px/s²,
점프 460px/s, 중력 980px/s², 통과 0.35초, 공격 재사용 0.4초를 조정한다.

- 지상·공중의 좌우 이동 방식은 같고, 양쪽을 동시에 누르면 이동 축은 0이다.
- 점프는 누른 순간만 실행한다. 버퍼·코요테 타임은 없다. 넉백 중 차단된 입력은
  피격 종료 후 자동 실행되지 않으며 다시 눌러야 한다.
- GroundChecker는 몸 중심에서 발밑 3px까지 아래로 검사한다. 월드 레이어 1만 검사하고
  위쪽 면 접촉·하강 상태에서 점프를 2회 회복한다. 플레이어 레이어는 2다.
- 상단 두 플랫폼은 아래에서 올라갈 수 있는 단방향 충돌이다.
  바닥 플랫폼은 전방향 고체이며 S로 통과할 수 없다.
- S 단독 입력은 발밑 단방향 플랫폼의 충돌과 GroundChecker 검사에서 그 플랫폼만
  일시 제외한다. 넉백 중 S는 차단한다. S+J는 하단 공격이며 동시에 통과하지 않는다.
- 플랫폼 폭은 바닥 920px, 상단 각 260px, 플레이어 크기는 36×52px이다.
- 다른 플레이어 머리 위에 떨어지면 올라서지 못하고 옆으로 미끄러진다(2026-10-10 요청). 위에서 닿는 순간 머리 중심에서 먼 쪽으로
  `movement_settings.tres`의 `stack_slide_speed`(300px/s)를 주며, 정확히 가운데면 플레이어 ID가 큰 쪽이 오른쪽으로 간다.
  밟힌 쪽은 영향이 없고, 머리 위에서는 점프 횟수도 회복되지 않는다.
- 플레이어끼리는 CharacterBody2D 충돌로 겹침을 방지한다. 대기·탈락 상태에서는
  충돌 레이어와 마스크를 모두 0으로 바꿔 보이지 않는 장애물이 남지 않게 한다.
- 시작점은 재스폰과 같은 방식으로 플랫폼 위 무작위, 서로 겹치지 않는 위치다(Design v2 결정).
  화면 영역은 1280×720이며 모든 플랫폼을 포함하고 창 크기에 맞춰 비율을 유지한다.

### 공격

캐릭터마다 `resources/characters/<id>.tres`(`CharacterDef`)에 기본 공격 5칸과 스킬 5칸을 둔다.
슬롯과 입력은 `GDD/characters/character-template.md` §6(2026-11-03 기획 제안, 확정 전 [검토])을 따른다.

| 슬롯 | 입력 | 테스트 파이터 (임시) | 범위 길이×폭 | 피해 | 배율 증가 | 기본 발사 속도 | 피격 제한 |
|---|---|---|---|---|---|---|---|
| 옆 | A/D+J (땅·공중) | `basic_attack.tres` | 몸 앞 80×70px | 10 | 12% | 420px/s | 0.35초 |
| 위·중립 | 땅에서 J 또는 W+J (같은 기술) | `basic_attack.tres` (옛 앞 공격 그대로) | 몸 앞 80×70px | 10 | 12% | 420px/s | 0.35초 |
| 아래 | 땅에서 S+J | `down_attack.tres` | 발밑 85×80px | 12 | 15% | 400px/s | 0.4초 |
| 공중 위 | 공중에서 J 또는 W+J (같은 기술) | `up_attack.tres` | 머리 위 100×60px | 8 | 10% | 450px/s | 0.4초 |
| 공중 아래 | 공중에서 S+J | `down_attack.tres` | 발밑 85×80px | 12 | 15% | 400px/s | 0.4초 |

- 여러 방향을 같이 누르면 위 > 아래 > 옆. 방향이 없으면 위(땅이면 위·중립, 공중이면 공중 위)다.
- `W`는 위 방향일 뿐 점프하지 않는다(2026-11-03). 점프는 `Space`(임시). 점프 키와 J를 같은 순간에 누르면 점프가 먼저 나가 공중 기술이 된다.
- 슬롯 이름의 "위"는 누르는 방향이다. 실제로 어디를 치는지는 공격 데이터(`anchor`, `launch_direction`)가 정한다.
- 범위 위치는 공격마다 `AttackData.anchor`(몸 앞 / 머리 위 / 발밑)로 정한다.
- 공중 칸이 비어 있으면 땅 칸의 공격·스킬을 쓴다.
- 테스트 파이터의 위·중립은 새로 정한 값이 없어 옛 앞 공격(`basic_attack.tres`)을 그대로 넣었다(임시). 그래서 땅에서 J만 눌러도 예전처럼 앞을 친다. 공중에서 J만 누르면 이제 공중 위 공격이 나간다.

선딜레이 없이 시작 프레임의 사각형 히트박스로 판정하고, 공격당 각 상대에게 한 번만 적중한다.
여러 상대에게 동시에 적중할 수 있으며, 키를 계속 눌러도 연속 공격하지 않는다.
입력 종료·피격·장외에서는 예약 공격을 취소한다. 넉백 입력 제한은 공격의 피격 시간으로 종료한다.
동시 다중 공격은 참가자 순서로 누적하며 마지막 공격 벡터가 발사 속도를 정한다.
향후 공격 주체가 없는 환경 피격도 명시적 방향으로 `receive_hit`에 전달한다.
피해와 배율은 독립이며 HP에 따른 탈락은 없다.

### 스킬 (임시 구현)

- 스킬 키 `K`(임시, 템플릿 §8.1 [검토]). 로컬 2인 테스트의 P2 공격 키였던 `K`는 `.`로, P2 스킬은 `/`, P2 점프는 `,`로 정했다.
- 스킬(`SkillData`)은 기본 공격과 같은 값(피해·배율·발사·범위·방향) + 재사용 대기 `cooldown` + 사용 순간 자기 속도 `self_velocity`(바라보는 쪽 기준)다.
- 판정은 기본 공격과 같다(시작 프레임 1회). 범위 길이나 폭이 0이면 이동만 하는 스킬이다.
- 같은 프레임에 J와 K를 누르면 기본 공격이 우선이다. 스킬도 기본 공격 재사용 대기(0.4초)를 함께 건다.
- 재사용 대기는 스킬별로 따로 센다. 공중 칸이 땅 스킬을 같이 쓰면 대기도 같이 쓴다. 장외·재스폰 때 모두 초기화한다.
- 입력 비트: 왼쪽 1, 오른쪽 2, 위 4, 아래 8, 공격 16, 스킬 32, 점프 64 (네트워크 입력 마스크 0~127).
- 아직 없음: 선딜레이·판정 유지·후딜레이, 투사체, 공중 사용 횟수 제한. 테스트 파이터는 스킬이 없다.

### 캐릭터별 이동값과 장외 라인 (임시)

- 이동값은 캐릭터의 `movement`(비어 있으면 `movement_settings.tres`)를 쓴다. 몸체 크기 36×52px와 점프 2회는 전 캐릭터 공통이다.
- 장외 라인은 이번 경기 참가자 중 2단 점프 복귀 거리가 가장 긴 값(수평·높이 각각 최댓값)으로 계산한다. 아직 복귀 거리를 늘리는 스킬은 계산에 넣지 않는다.

### 장외·재스폰

- 장외(즉사) 라인은 "밀려난 뒤 2단 점프로 돌아올 수 없는 거리" 기준이다(2026-10-10 요청). 중심 좌표가 라인에 닿으면 즉시 스톡 1개를 잃는다.
  - 2단 점프 회복 거리: 수평 = 이동속도 × 4 × 점프속도 / 중력(체공 2회) = 약 488px, 상승 = 점프속도² / 중력 = 약 216px.
  - 좌우 라인 = 전체 플랫폼 끝 ± (수평 회복 거리 + 여유 40px) → x ≈ -348 / 1628.
  - 아래 라인 = 가장 낮은 플랫폼 윗면 + (상승 거리 + 여유 40px) → y ≈ 796.
  - 위 라인은 떨어지면 돌아오므로 회복 기준이 아니라 화면 위 160px(`ring_out_margin`)이다.
  - 이동·점프 값을 바꾸면 라인이 자동으로 다시 계산된다. 여유값은 `combat_rules.tres`의 `blast_safety_margin`.
  - 라인은 경기장에 옅은 빨간 점선으로 그리며, 화면이 1280×720보다 넓거나 길 때 보인다.
- 재스폰 대기 3초(Design v2 결정).
- 발사 속도 = 기본 속도 × (1 + 현재 배율 × 증가 계수 / 100). 증가 계수는 1,
  상한 0은 무제한이다. 음수 피해·증가량은 0으로 제한한다.
- 재스폰은 발이 플랫폼 상단에 닿는 격자 후보 중 점유된 위치·가장자리를 제외해 무작위 선택한다.
  빈 후보가 없으면 위치가 확보될 때까지 재시도한다.
- 장외는 속도·피격·예약 공격·쿨다운·통과 상태·배율·피해를 초기화한다.
  마지막 스톡 오브젝트는 숨기고 현재 판에 다시 참여시키지 않는다.
- 무적 3초는 피해·배율·발사·피격 상태·외부 impulse를 막는다.
  본인 이동·중력·지형 충돌·장외 판정은 적용된다. 새 외부 효과도 공통 피격 API를 사용한다.
- 한 프레임의 모든 장외를 처리한 다음 생존자 1명은 승리, 0명은 무승부다.

### 네트워크·경기 운영

- ENet UDP, 최대 4명, 호스트 플레이어도 참가한다. 호스트만 시작을 확정하고, 재경기는 전원 결과 확인 후 같은 방 S2로 돌아간다.
- 최소 지원 환경은 한 컴퓨터에서 2개 이상의 독립 프로세스다.
  주소 입력은 가능하지만 다른 컴퓨터 간 접속 및 인터넷 운영은 별도 검증 대상이다.
- 호스트만 이동·충돌·공격·스톡·타이머·승패를 계산한다. 클라이언트는 자기 키 입력만 보내며
  호스트는 RPC 송신자 ID로 플레이어를 찾는다. 클라이언트가 타인 ID·좌표·스톡을 지정할 수 없다.
- 입력은 신뢰성 있는 순서 전송, 상태는 20Hz 스냅샷, 최종 결과는 신뢰성 있는 전송이다.
  입력이 0.5초 이상 오지 않으면 키 상태를 해제한다. 라운드 번호·프레임 번호로 이전 상태를 무시한다.
- 경기 중 새 참가를 거부하고, 재접속은 메뉴로 돌아간 뒤 다음 대기방에서 새 참가자로 받는다.
- 클라이언트 연결 종료는 해당 판 기권·탈락이다. 호스트 연결 종료는 경기 종료 후 메뉴 복귀다.
- 재경기는 모든 참가자의 스톡 3개·배율 0%, 입력·무적·타이머를 새로 만든다.
- 연결 실패는 참여 팝업에 안내하며 8초 연결 제한을 둔다. 방 가득·진행 중·버전 불일치는 호스트가 사유를 보낸 뒤 연결을 끊는다.

## 자동 검증

```powershell
godot --headless --path . --script res://tests/combat_test.gd
godot --headless --path . --script res://tests/gameplay_test.gd
godot --headless --path . --script res://tests/ui_flow_test.gd
```

네트워크 테스트는 두 터미널에서 호스트를 먼저 실행한다(전용 포트 27849).

```powershell
godot --headless --path . --script res://tests/network_peer.gd -- host
godot --headless --path . --script res://tests/network_peer.gd -- client
```

대기방 기능(입장 알림·닉네임·채팅과 0.5초 제한·참가자의 방 설정 거부·강제 퇴장과 재입장·방 닫기·경기 중 참가 거부)은
`tests/lobby_peer.gd`(포트 27848)로 같은 방식으로 검사한다.
`ui_flow_test.gd`는 메인 메뉴 → 게임하기 → 방 참여 팝업 → 온라인 대기방 → 경기 → 결과 → 훈련장 대기방 → 허수아비 경기 → 결과를 지나며
각 주요 장면을 "[장면] ..." 텍스트로 출력한다.
화면 캡처는 창 모드로 `--script res://tests/capture_ui.gd`를 실행하면 `.godot/test-output`에 저장된다(`-- out=절대경로`로 바꿀 수 있음).

공유 대기방·준비·시작·입력 소유권·피격 배율·장외·재스폰 무적·최종 결과·재경기·기권을 검사한다.

Windows에서는 전체 테스트를 한 번에 실행할 수 있다.
