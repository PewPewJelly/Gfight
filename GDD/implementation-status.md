# GDD 전체 구현 현황

## 실행 및 참가

Godot 4.7.2로 `project.godot`을 열고 F5를 누른다. 첫 화면은 S1 메인 메뉴다.
화면 구성은 `Design/ui-ux-scenes-v2.pdf`(최신)와 `Design/match-flow-scene-ux.md` v2를 따른다.

- 같은 프로젝트를 두 번 실행한다. 첫 창에서 **게임 생성**, 두 번째 창에서 **게임 참여** →
  주소 `127.0.0.1` 또는 `IP:포트`(빈 칸이면 127.0.0.1:27840) → **참여**(Enter).
- S2 대기실에서 참가자가 **준비 완료**를 누르고, 참가 2명 이상 + 참가자 전원 준비이면 호스트의 **경기 시작**이 켜진다.
- S3: 3초 카운트다운 뒤 조작을 시작한다. 모든 창은 WASD/J로 자기 플레이어만 조작한다. 경기 중 Esc 나가기는 없다.
- S4: 각자 Enter로 확인하고, 남아 있는 전원이 확인하면 같은 방 S2로 돌아간다(준비 상태 초기화).
- 방을 떠나는 길은 S2 **나가기**뿐이다. 호스트가 나가면 확인창 후 방이 닫히고 참가자는 S1 토스트를 본다.
- 로컬 2인(`Session.local_game()`)은 테스트용으로 남아 있고 메뉴 버튼은 없다. P1 WASD/J, P2 방향키/K.

### 화면 크기·전체화면

- 기본 실행은 전체화면(`window/size/mode=3`). F11 또는 Alt+Enter로 창 모드 전환(한 컴퓨터에서 두 개 실행할 때).
- 기준 해상도 1280×720, `stretch/mode=canvas_items`, `stretch/aspect=expand`. 16:9가 아닌 화면에서는 레터박스 없이 UI가 화면 가장자리에 붙고,
  경기장은 Camera2D로 화면 가운데에 고정되어 여백만 늘어난다. 여백 색은 배경색(`default_clear_color`)과 같다.
- 장외 판정 영역은 화면 크기와 상관없이 1280×720 기준 그대로다.

### UI·흐름 임시값 ([제안]/[미정])

- 시작 카운트다운 3초(`combat_rules.tres` `start_countdown`), "시작!" 0.7초, 결과 화면 전 정지 0.8초, 페이드 0.2초, 토스트 3초.
- 배율 색: 0% 흰색 → 100% 주황 → 200% 빨강(`UiStyle.DANGER_*`).
- 킬: 장외된 플레이어를 마지막으로 때린 상대에게 1킬. 마지막 공격자 기록은 장외 때 지운다. 자기 낙사·연결 끊김은 킬 없음.
- 준 배율: 내 공격이 실제로 올린 상대 배율의 합.
- 순위: 승자 1위, 나머지는 늦게 탈락한 순. 같은 프레임 탈락은 같은 순위(무승부는 공동 1위, 왕관 없음).
- 결과 화면에서 확인하지 않는 사람은 계속 기다린다(자동 확인 [미정]).
- 랜덤 시작 위치 간 최소 거리는 겹침 방지만 적용한다([미정]).
- 호스트는 준비 집계에서 빠지고 [경기 시작]이 준비를 대신한다.
- 방 가득 참을 알리려고 ENet 서버는 4명 + 거부용 1자리로 연다.
- 버전 비교는 `application/config/version`(0.1.0) 문자열 일치.
- 미구현 [제안]: 장외 섬광·카드 흔들림, 재스폰 직전 위치 표식.

## 미정 항목의 임시 구현 정책

다음은 테스트 가능한 구현을 위한 기본값이며 게임 규칙 확정이 아니다.
디자인 변경 시 Resource와 해당 정책을 함께 갱신한다.

### 이동·플랫폼

`resources/movement_settings.tres`에서 이동 260px/s, 가속·감속 1600px/s²,
점프 460px/s, 중력 980px/s², 통과 0.35초, 공격 재사용 0.4초를 조정한다.

- 지상·공중의 좌우 이동 방식은 같고, 양쪽을 동시에 누르면 이동 축은 0이다.
- 점프는 누른 순간만 실행한다. 버퍼·코요테 타임은 없다. 넉백 중 차단된 입력은
  피격 종료 후 자동 실행되지 않으며 다시 눌러야 한다.
- GroundChecker는 몸 중심에서 발밑 3px까지 아래로 검사한다. 월드 레이어 1만 검사하고
  위쪽 면 접촉·하강 상태에서 점프를 2회 회복한다. 플레이어 레이어는 2다.
- 상단 두 플랫폼은 아래에서 올라갈 수 있는 단방향 충돌이다.
  바닥 플랫폼은 전방향 고체이며 S로 통과할 수 없다.
- S 단독 입력은 발밑 단방향 플랫폼의 충돌과 GroundChecker 검사에서 그 플랫폼만
  일시 제외한다. 넉백 중 S는 차단한다. S+J는 하단 공격이며 동시에 통과하지 않는다.
- 플랫폼 폭은 바닥 920px, 상단 각 260px, 플레이어 크기는 36×52px이다.
- 플레이어끼리는 CharacterBody2D 충돌로 겹침을 방지한다. 대기·탈락 상태에서는
  충돌 레이어와 마스크를 모두 0으로 바꿔 보이지 않는 장애물이 남지 않게 한다.
- 시작점은 재스폰과 같은 방식으로 플랫폼 위 무작위, 서로 겹치지 않는 위치다(Design v2 결정).
  화면 영역은 1280×720이며 모든 플랫폼을 포함하고 창 크기에 맞춰 비율을 유지한다.

### 공격

| 종류 | 선택 | 범위 길이×폭 | 피해 | 배율 증가 | 기본 발사 속도 | 피격 제한 |
|---|---|---|---|---|---|---|
| 앞 | J 또는 A/D+J | 80×70px | 10 | 12% | 420px/s | 0.35초 |
| 위 | W+J | 100×60px | 8 | 10% | 450px/s | 0.4초 |
| 아래 | S+J | 85×80px | 12 | 15% | 400px/s | 0.4초 |

설정은 `basic_attack.tres`, `up_attack.tres`, `down_attack.tres`다.
W·S가 동시에 눌렸으면 위 공격이 우선이다. 방향키가 없으면 현재 바라보는 쪽으로
앞 공격을 한다. 앞 공격은 해당 방향과 약간 위, 위·아래 공격은 각 수직 방향으로 발사한다.
선딜레이 없이 시작 프레임의 사각형 히트박스로 판정하고, 공격당 각 상대에게 한 번만 적중한다.
여러 상대에게 동시에 적중할 수 있으며, 키를 계속 눌러도 연속 공격하지 않는다.
입력 종료·피격·장외에서는 예약 공격을 취소한다. 넉백 입력 제한은 공격의 피격 시간으로 종료한다.
동시 다중 공격은 참가자 순서로 누적하며 마지막 공격 벡터가 발사 속도를 정한다.
향후 공격 주체가 없는 환경 피격도 명시적 방향으로 `receive_hit`에 전달한다.
피해와 배율은 독립이며 HP에 따른 탈락은 없다.

### 장외·재스폰

- `combat_rules.tres`: 화면 네 방향 밖 160px, 중심 좌표 기준, 재스폰 대기 3초(Design v2 결정).
- 발사 속도 = 기본 속도 × (1 + 현재 배율 × 증가 계수 / 100). 증가 계수는 1,
  상한 0은 무제한이다. 음수 피해·증가량은 0으로 제한한다.
- 재스폰은 발이 플랫폼 상단에 닿는 격자 후보 중 점유된 위치·가장자리를 제외해 무작위 선택한다.
  빈 후보가 없으면 위치가 확보될 때까지 재시도한다.
- 장외는 속도·피격·예약 공격·쿨다운·통과 상태·배율·피해를 초기화한다.
  마지막 스톡 오브젝트는 숨기고 현재 판에 다시 참여시키지 않는다.
- 무적 3초는 피해·배율·발사·피격 상태·외부 impulse를 막는다.
  본인 이동·중력·지형 충돌·장외 판정은 적용된다. 새 외부 효과도 공통 피격 API를 사용한다.
- 한 프레임의 모든 장외를 처리한 다음 생존자 1명은 승리, 0명은 무승부다.

### 네트워크·경기 운영

- ENet UDP, 최대 4명, 호스트 플레이어도 참가한다. 호스트만 시작을 확정하고, 재경기는 전원 결과 확인 후 같은 방 S2로 돌아간다.
- 최소 지원 환경은 한 컴퓨터에서 2개 이상의 독립 프로세스다.
  주소 입력은 가능하지만 다른 컴퓨터 간 접속 및 인터넷 운영은 별도 검증 대상이다.
- 호스트만 이동·충돌·공격·스톡·타이머·승패를 계산한다. 클라이언트는 자기 키 입력만 보내며
  호스트는 RPC 송신자 ID로 플레이어를 찾는다. 클라이언트가 타인 ID·좌표·스톡을 지정할 수 없다.
- 입력은 신뢰성 있는 순서 전송, 상태는 20Hz 스냅샷, 최종 결과는 신뢰성 있는 전송이다.
  입력이 0.5초 이상 오지 않으면 키 상태를 해제한다. 라운드 번호·프레임 번호로 이전 상태를 무시한다.
- 경기 중 새 참가를 거부하고, 재접속은 메뉴로 돌아간 뒤 다음 대기방에서 새 참가자로 받는다.
- 클라이언트 연결 종료는 해당 판 기권·탈락이다. 호스트 연결 종료는 경기 종료 후 메뉴 복귀다.
- 재경기는 모든 참가자의 스톡 3개·배율 0%, 입력·무적·타이머를 새로 만든다.
- 연결 실패는 참여 팝업에 안내하며 8초 연결 제한을 둔다. 방 가득·진행 중·버전 불일치는 호스트가 사유를 보낸 뒤 연결을 끊는다.

## 자동 검증

```powershell
godot --headless --path . --script res://tests/combat_test.gd
godot --headless --path . --script res://tests/gameplay_test.gd
godot --headless --path . --script res://tests/ui_flow_test.gd
```

네트워크 테스트는 두 터미널에서 호스트를 먼저 실행한다(전용 포트 27849).

```powershell
godot --headless --path . --script res://tests/network_peer.gd -- host
godot --headless --path . --script res://tests/network_peer.gd -- client
```

대기방 닫기·경기 중 참가 거부는 `tests/lobby_peer.gd`(포트 27848)로 같은 방식으로 검사한다.
화면 캡처는 창 모드로 `--script res://tests/capture_ui.gd`를 실행하면 `.godot/test-output`에 저장된다.

공유 대기방·준비·시작·입력 소유권·피격 배율·장외·재스폰 무적·최종 결과·재경기·기권을 검사한다.

Windows에서는 전체 테스트를 한 번에 실행할 수 있다.

```powershell
.\tests\run_checks.ps1 -GodotPath 'Godot 실행파일의 절대 경로'
```

### 검증 결과 (2026-10-04)

- Godot 4.7.2: 전투 규칙 검증 실패 0건.
- 실제 2D 물리·메뉴·방향별 공격·통과·2단 점프·4명 시작 위치 검증 실패 0건.
- 독립 ENet 호스트/클라이언트 2개 프로세스: 양쪽 실패 0건.
  피격·장외·재스폰 무적·결과·재경기·기권 동기화를 확인했다.
- OpenGL Compatibility 렌더러로 메뉴·대기방·경기·결과를 캡처하여 배치·문구를 확인했다.
  마지막 캡처 실행의 런타임 오류는 없다. 캡처는 `.godot/test-output`에 둔다.
- 제한된 실행 환경에서는 localhost UDP 접속이 차단되어 네트워크 검증을 일반 권한으로 실행했다.

네트워크 API 참고: [Godot 공식 고수준 멀티플레이 문서](https://docs.godotengine.org/en/stable/tutorials/networking/high_level_multiplayer.html).
