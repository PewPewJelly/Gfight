# 공격 구현 핸드오프

## 범위와 근거

첨부된 공격 메모와 이번 요청만 반영한다. 메모에서 정하지 않은 공격 종류, 판정 방식, 수치는 임의로 확정하지 않는다.

## 확정된 요구사항

| 항목 | 요구 동작 |
|---|---|
| 공격 입력 | `J`를 누르면 공격한다. |
| 방향 관련 입력 | 위쪽은 `W`, 앞쪽은 `A`·`D`, 아래쪽은 `S`와 연결된다. |
| 공격 범위 | 공격에 따라 범위가 다르다. |
| 명중 효과 | 공격이 상대에게 맞으면 맞은 상대의 넉백 배율이 증가한다. |
| 피격 중 공격 제한 | 피격으로 인한 넉백 중에는 공격할 수 없다. |

## 구현 시 처리 흐름

1. `J` 공격 입력을 받는다.
2. **임시 조건:** 현재 `넉백 중` 상태라면 공격 시작을 막는다. 넉백 중이 아니라면 공격을 시작할 수 있다.
3. 공격의 방향과 범위에 맞게 명중 여부를 판정한다. 방향 결정 규칙, 공격별 범위와 판정 방식은 아래 미정 사항이 결정되어야 구체화할 수 있다.
4. 명중이 확인되면 **맞은 상대**의 넉백 배율을 증가시킨다. 증가량·상한·유지 및 초기화 규칙은 미정이다.

### 넉백 중 공격 제한의 임시 적용

`넉백 중 공격 불가`는 **임시 조치**로, 공격 가능 여부를 가리는 조건만 먼저 마련한다. 실제 넉백 시스템이 들어오면 그 시스템의 상태·시작 및 종료 기준에 맞춰 이 조건을 **변경한다**. 현재 메모만으로 넉백 상태를 판정하는 로직이나 지속시간을 새로 정의하지 않는다.

## 확인 기준

1. 공격 가능한 상태에서 `J` 입력이 공격 시작으로 연결된다.
2. 임시 `넉백 중` 조건이 참이면 `J` 입력으로 공격이 시작되지 않는다.
3. 공격이 상대에게 맞으면 공격자가 아닌 **맞은 상대**의 넉백 배율이 증가한다.
4. 공격이 빗나가면 넉백 배율 증가 처리가 실행되지 않는다.
5. 위·앞·아래 방향 입력과 공격 범위는 아래 미정 사항을 확정한 뒤 세부 확인 기준을 작성한다.

## 미정 사항 — 구현 전에 결정 필요

| 항목 | 확인할 내용 |
|---|---|
| 방향 결정 | `J`와 `W`·`A`·`D`·`S`를 어떤 방식으로 조합하는지, 방향 입력이 없거나 여러 방향을 동시에 누를 때 어떤 방향으로 공격하는지 |
| ‘앞’의 의미 | `A`·`D`가 각각 좌·우 공격을 뜻하는지, 캐릭터가 바라보는 방향을 뜻하는지 |
| 공격 종류 | 공격이 몇 종류인지, 각 공격을 어떤 입력·상태로 선택하는지 |
| 공격 범위와 판정 | 공격별 범위, 판정 모양·위치, 유효 시간, 대상 및 다중 명중 처리 |
| 공격 시간 규칙 | 선딜레이·후딜레이, 연속 공격·입력 재사용·공격 취소 허용 여부 |
| 넉백 배율 | 증가량, 누적 방식, 최대치, 초기화 조건, 실제 넉백에 반영하는 시점 |
| 공격 제한 | 실제 넉백 시스템 도입 전 임시 조건에 값을 제공할 주체와, 도입 후 연결할 넉백 상태 |

미정 항목에는 임시 수치나 동작을 넣지 않는다. 특히 공격 방향·종류·범위가 정해져야 실제 공격 판정을 완성할 수 있다.
