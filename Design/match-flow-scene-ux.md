# 경기 흐름 씬 구성안 (UI/UX)

> 근거: `GDD/match-menu-multiplayer-handoff.md` (보조: `GDD/basicRule.md`, `GDD/defeatNrule.md`)
> 기존 시안 `S1_main_menu` / `S2_lobby_placeholder`의 번호 체계(S1, S1-1, S2…)를 이어서 쓴다.
> 표시: **[확정]** GDD 규칙, **[결정]** 기획자가 이 문서 검토에서 정한 값, **[제안]** 이 문서가 고른 기본값, **[미정]** 아직 정하지 않은 항목.

### 변경 이력

- **v2 (2026-10-10)**: 기획자 코멘트 반영.
  - 결정 사항 1~10, 12 확정 (8장 참고).
  - S2: 참가자 "준비 완료" 추가. 전원 준비가 되어야 호스트가 시작할 수 있다.
  - S3: 재스폰 대기 3초, 시작·재스폰 위치는 플랫폼 위 랜덤.
  - S4: 재경기/나가기 버튼을 없애고, 플레이어별 순위·통계 표시 후 전원이 Enter로 "확인 완료"하면 S2로 돌아가는 방식으로 변경.

## 1. 전체 흐름

```
 [S0 부팅] ─▶ [S1 메인 메뉴] ──게임 생성──────────────▶ [S2 대기실(호스트)]
                 │                                         │
                 ├─게임 참여─▶ [S1-1 IP 입력 팝업] ──성공──▶ [S2 대기실(참가자)]
                 │                 │ 실패: 팝업 안에서 오류 표시   │
                 │                 └ 취소/Esc ─▶ S1               │ 인원 ≥ 2 + 전원 준비 완료
                 └─게임 종료─▶ 앱 종료                             │ → 호스트가 시작
                        ▲                                         ▼
                        │ S2 [나가기]                        [S3 경기 HUD]
                        │                                (S3-1 나가기 오버레이)
                        │                                          │ 승자 확정 / 무승부
                        │                                          ▼
                        │                                  [S4 결과 화면]
                        │                                          │ 전원 Enter "확인 완료"
                        │                                          ▼
                        └──────────────────────────────── [S2 대기실] (같은 방, 스톡 3 초기화)
```

- 경기가 끝나면 항상 같은 방의 S2로 돌아간다. 방을 떠나는 길은 S2의 [나가기] 하나다. **[결정]**
- 경기 중 새 참가자는 들어올 수 없다(난입 불가). 새 참가자는 S2에서만 들어온다. **[결정]**

공통 원칙
- 씬 전환은 짧은 페이드(0.2초 내외)로 통일한다. **[제안]**
- 네트워크 대기가 있는 모든 동작에는 "진행 중" 상태(버튼 비활성 + 문구)를 둔다. 같은 요청을 두 번 보내지 않게 한다.
- 호스트와 연결이 끊기면 어느 화면에서든 S1로 돌아가고, S1에 끊김 이유를 토스트로 보여 준다. **[제안]**
- 온라인 경기이므로 일시정지는 없다. **[결정]**
- 기본 도형 + 텍스트 시안 스타일(어두운 남색 배경 `#101927`, 강조색 `#4f7cff`, 오류색 `#ff5a5a`)을 그대로 쓴다.

## 2. S1 메인 메뉴

**목적**: 게임 실행 직후 멀티플레이어 경기 참여 흐름으로 들어가는 입구. **[확정]** (처리 흐름 1)

```
┌──────────────────────────────────┐
│                                  │
│          ┌──────────────┐        │
│          │    Gfight    │        │
│          │ ──────────── │        │
│          │ [ 게임 참여 ] │        │
│          │ [ 게임 생성 ] │        │
│          │ [ 게임 종료 ] │        │
│          └──────────────┘        │
│                        v0.x.x    │
└──────────────────────────────────┘
```

핵심 요소
- 제목, 버튼 3개(참여 / 생성 / 종료). 기존 S1 시안 그대로.
- 키보드·게임패드 포커스 이동(위/아래 + 확인). 첫 포커스는 "게임 참여". **[제안]**
- 우하단 작은 버전 표기: 다른 컴퓨터끼리 접속할 때 빌드가 달라 실패하는 원인을 찾는 용도. **[제안]**

상태와 예외
| 상황 | 표시 |
|---|---|
| 게임 생성 중 | 버튼 비활성, "방을 만드는 중…" |
| 생성 실패(포트 사용 중 등) | 토스트 "방을 생성할 수 없습니다." (기존 시안 문구) |
| 호스트와 끊겨 돌아옴 | 토스트 "호스트와의 연결이 끊어졌습니다." **[제안]** |

## 3. S1-1 게임 참여 팝업

**목적**: 참가할 방의 IP를 입력한다. 별도 씬이 아니라 S1 위에 뜨는 오버레이.
방 목록이나 방 코드 없이 **IP 직접 입력만** 허용하고, **다른 컴퓨터 간 접속을 지원**한다. **[결정]**

```
┌──────────────────────────────────┐
│░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░│  ← 화면 65% 어둡게
│░░░░┌────────────────────────┐░░░░│
│░░░░│ 게임 참여               │░░░░│
│░░░░│ 주소 [127.0.0.1:27840 ] │░░░░│
│░░░░│ 해당 주소의 게임을 찾을 │░░░░│  ← 실패 시 빨간 글씨
│░░░░│ 수 없습니다.            │░░░░│
│░░░░│        [취소] [참여]    │░░░░│
│░░░░└────────────────────────┘░░░░│
└──────────────────────────────────┘
```

핵심 요소
- 입력 형식 `IP` 또는 `IP:포트`, 기본 포트 27840. 빈 칸이면 placeholder `127.0.0.1`(한 컴퓨터 개발 환경용). **[제안]**
- 마지막으로 성공한 주소를 기억해 미리 채움. **[제안]**
- Enter = 참여, Esc = 취소.

상태와 예외
| 상황 | 표시 |
|---|---|
| 접속 시도 중 | 참여 버튼 → "접속 중…" 비활성, 입력칸 잠금, 취소는 가능 |
| 형식 오류(포트가 숫자 아님 등) | 요청 없이 즉시 "주소 형식이 올바르지 않습니다." **[제안]** |
| 응답 없음/거부 (최대 8초) | "해당 주소의 게임을 찾을 수 없습니다." |
| 방이 가득 참 (4명) | "방이 가득 찼습니다." **[결정: 최대 4명]** |
| 경기 진행 중인 방 (S3·S4) | "이미 경기가 진행 중입니다." **[결정: 난입 불가]** |
| 버전 불일치 | "게임 버전이 다릅니다." **[제안]** |

오류가 나도 팝업을 닫지 않고 입력값을 유지해 바로 고쳐 다시 시도하게 한다.

## 4. S2 대기실 (로비)

**목적**: 참가자를 구별하고 인원수를 확인하며, 2명 이상이고 전원이 준비되었을 때만 시작할 수 있게 한다. **[확정]** (처리 흐름 2–3) + **[결정]** (준비 완료)

```
┌───────────────────────────────────────────────┐
│ 대기실                 방 주소 192.168.0.5:27840 [복사] │
├───────────────────────────────────────────────┤
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │  P1 ★   │ │  P2     │ │  P3     │ │  빈 자리  │ │
│ │ (호스트) │ │ (나)    │ │         │ │   …     │ │
│ │ ■ 빨강  │ │ ■ 파랑  │ │ ■ 초록  │ │         │ │
│ │  호스트  │ │ ✔ 준비  │ │ 대기 중  │ │         │ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
│                                               │
│  참가 인원 3 / 4   준비 1 / 2      스톡 3          │
│                                               │
│  [ 나가기 ]          [ 준비 완료 ] / [ 경기 시작 ] │
└───────────────────────────────────────────────┘
```

핵심 요소
- **플레이어 슬롯**: 번호(P1~P4), 고유 색, 호스트 표시(★), 내 슬롯 표시("나" + 테두리 강조), 준비 상태. 각 클라이언트가 자신이 조작할 플레이어를 구별해야 한다는 확정 규칙을 로비부터 시각화한다.
- 슬롯 색은 경기 HUD·캐릭터 색과 같게 맞춘다. 로비에서 본 색이 경기 중 "나"를 찾는 단서가 된다. **[제안]**
- **참가 인원 카운터** `n / 4`. 프로토타입은 최대 4명. **[결정]**
- **준비 카운터** `준비 n / 참가자 수`. 호스트는 [경기 시작]을 누르는 것이 곧 준비이므로 준비 집계에서 빠진다. **[제안]**
- **방 주소 + 복사 버튼**: 호스트가 다른 컴퓨터의 참가자에게 알려 줄 IP. 같은 네트워크 IP를 우선 표시한다. **[제안]**
- **버튼 (역할별)**
  - 참가자: [준비 완료] 토글. 누르면 "✔ 준비"로 바뀌고 다시 누르면 취소된다. **[결정]**
  - 호스트: [경기 시작]. 조건이 맞을 때만 활성화된다. **[결정]**
- **규칙 요약**: "스톡 3". 이후 규칙이 늘어나면 이 자리에 둔다.

경기 시작 버튼 상태 (호스트 화면)
| 조건 | 버튼 | 보조 문구 |
|---|---|---|
| 참가 인원 1명 | 비활성 | "2명 이상이 모여야 시작할 수 있습니다." **[확정]** |
| 2명 이상, 준비 안 된 참가자 있음 | 비활성 | "모든 참가자가 준비를 마쳐야 시작할 수 있습니다." **[결정]** |
| 2명 이상, 참가자 전원 준비 | 활성(강조색) | – |
| 시작 요청 후 | 비활성 "시작하는 중…" | 중복 시작 방지 |

참가자 화면 문구
| 상태 | 문구 |
|---|---|
| 준비 전 | "준비가 되면 [준비 완료]를 눌러 주세요." |
| 준비 완료, 다른 사람 대기 | "다른 참가자를 기다리는 중…" |
| 전원 준비 | "호스트가 시작하기를 기다리는 중…" |

예외
| 상황 | 처리 |
|---|---|
| 참가자 입장 | 슬롯 추가(준비 안 됨 상태), 짧은 알림 "P3 님이 들어왔습니다." 전원 준비였다면 시작 버튼이 다시 비활성화된다. |
| 참가자 퇴장 | 슬롯 비우기, 알림 "P3 님이 나갔습니다." |
| 시작 순간 인원이 2명 미만이 되거나 누가 준비를 취소함 | 시작 취소, 버튼 비활성으로 복귀 |
| 호스트가 [나가기] | 확인창 "방을 닫으면 모두 나가게 됩니다." 확인 시 참가자 전원 S1, 토스트 "호스트가 방을 닫았습니다." **[제안]** |
| S4에서 돌아옴 | 모든 참가자의 준비 상태를 초기화한다. 다음 판도 전원 준비 후 시작한다. **[제안]** |

## 5. S3 경기 HUD

**목적**: 모든 참가자에게 참가 인원, 각 플레이어 스톡, 경기 시작·종료를 일관되게 보여 준다. **[확정]** (처리 흐름 4)
카메라는 플랫폼 전체가 한눈에 보이도록 고정한다. **[확정]** (basicRule) HUD는 플랫폼을 가리지 않도록 화면 아래 띠에 모은다.

```
┌──────────────────────────────────────────┐
│                  3 · 2 · 1 · 시작!          │  ← 시작 카운트다운 [제안]
│                                          │
│        ▼나                                │
│      ═════════        ═════════            │
│              ═══════════════              │
│                                          │
├──────────────────────────────────────────┤
│ ┌P1 빨강──┐ ┌P2 파랑(나)┐ ┌P3 초록──┐ ┌P4 노랑──┐ │
│ │  42%   │ │  118%  │ │ 재등장 2 │ │ 탈락   │ │
│ │ ● ● ●  │ │ ● ○ ○  │ │ ● ● ○  │ │ ○ ○ ○  │ │
│ └────────┘ └────────┘ └────────┘ └────────┘ │
└──────────────────────────────────────────┘
```

경기 시작
- 각 플레이어는 **플랫폼 위 랜덤 위치**에서 시작한다. 서로 같은 위치에 겹치지 않는다. **[결정]** + **[확정: 서로 다른 위치]**
- 시작 위치가 랜덤이므로, 카운트다운 동안 각 캐릭터 머리 위에 번호·색 표시를 크게 띄워 "나는 어디서 시작하는지"를 먼저 알려 준다. **[제안]**

핵심 요소
- **플레이어 카드(하단)**: 색, 번호, 넉백 배율 %(defeatNrule의 넉백 배율), 남은 스톡 아이콘 3개. 카드 순서는 슬롯 번호 고정.
- **내 캐릭터 표시**: 머리 위 "▼나" 또는 내 색의 화살표, 내 카드 테두리 강조. **[확정: 자기 플레이어 구별]**
- **넉백 배율 색 변화**: 0%(흰색) → 높을수록 주황 → 빨강. 위험도를 숫자를 읽지 않고도 알게 한다. **[제안]**
- **시작 카운트다운**: 모든 클라이언트가 같은 시점에 조작을 시작한다는 신호. **[제안]**

경기 중 이벤트 표현
| 이벤트 | 표현 |
|---|---|
| 장외 | 나간 방향 화면 가장자리에 색 섬광, 해당 카드 스톡 아이콘 하나가 빠지며 흔들림, 배율 0%로 리셋 |
| 재스폰 대기 **3초** **[결정]** | 카드에 "재등장 3 · 2 · 1" 카운트다운 |
| 재스폰 위치 | 플랫폼에 닿아 있는 랜덤 위치 **[확정]**. 나타나기 직전 그 위치에 플레이어 색 표식을 잠깐 보여 준다. **[제안]** |
| 재스폰 무적 3초 **[확정]** | 캐릭터 깜빡임 또는 반투명, 카드에 무적 게이지(3초 감소) |
| 스톡 0 | 카드 회색 처리 + "탈락", 캐릭터 제거. 본인 화면에는 "탈락했습니다. 관전 중" 띠 **[제안]** |
| 화면 밖에 있는 플레이어 | 화면 가장자리에 색 화살표 (장외 판정 거리 전) **[제안]** |

S3-1 나가기 오버레이 (Esc)
- 일시정지는 없다. 오버레이만 띄우고 경기는 계속 진행된다. **[결정]**
- 메뉴: "계속" / "경기 나가기"(확인창). 경기 중 나간 플레이어는 스톡 0과 같이 탈락 처리한다. **[제안]**

연결 예외
| 상황 | 처리 |
|---|---|
| 참가자 끊김 | 카드에 "연결 끊김" 표시, 스톡 0과 같이 탈락 처리. 재접속은 받지 않는다. **[제안]** (난입 불가 결정과 같은 이유) |
| 남은 인원이 1명이 됨 | 그 플레이어 승리로 S4 **[제안]** |
| 호스트 끊김 | 경기 중단 → S1, 토스트 "호스트와의 연결이 끊어졌습니다." |

## 6. S4 결과 화면

**목적**: 승자를 확정해 모든 참가자에게 같은 결과를 보여 주고, 전원이 확인하면 같은 방 대기실로 돌아간다. **[확정]** (처리 흐름 6) + **[결정]**

```
┌───────────────────────────────────────────────┐
│                    P2 승리!                      │
│                                               │
│ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ │
│ │   P1    │ │   P2    │ │   P3    │ │   P4    │ │
│ │  ■ 빨강  │ │ ■ 파랑(나)│ │  ■ 초록  │ │  ■ 노랑  │ │
│ │  3위    │ │ 👑 1위   │ │  2위    │ │  4위    │ │
│ ├─────────┤ ├─────────┤ ├─────────┤ ├─────────┤ │
│ │ 킬  1   │ │ 킬  4   │ │ 킬  2   │ │ 킬  0   │ │
│ │ 준 배율  │ │ 준 배율  │ │ 준 배율  │ │ 준 배율  │ │
│ │  186%   │ │  412%   │ │  240%   │ │  95%    │ │
│ │ 남은 스톡 0│ │ 남은 스톡 1│ │ 남은 스톡 0│ │ 남은 스톡 0│ │
│ ├─────────┤ ├─────────┤ ├─────────┤ ├─────────┤ │
│ │✔ 확인 완료│ │ 대기 중  │ │✔ 확인 완료│ │ 대기 중  │ │
│ └─────────┘ └─────────┘ └─────────┘ └─────────┘ │
│                                               │
│      Enter를 눌러 확인   (확인 완료 2 / 4)          │
└───────────────────────────────────────────────┘
```

진입
- 마지막 장외 직후 0.5~1초 슬로/정지 연출 뒤 결과로 넘어가 "왜 끝났는지" 보이게 한다. **[제안]**

핵심 요소 **[결정]**
- **상단 결과 문구**: "P2 승리!" (승자 색). 무승부면 "무승부".
- **플레이어별 열 (P1 | P2 | P3 | P4)**: 슬롯 번호 순서로 고정 배치하고 각 열에 순위를 표시한다. 1위 열은 왕관과 승자 색 테두리로 강조한다. 내 열은 S2·S3처럼 "(나)"와 테두리로 표시한다.
- **순위 기준**: 1위는 승자, 나머지는 늦게 탈락한 순서대로 매긴다. **[제안]**
- **간단한 통계** (항목은 아래 "통계 정의" 참고)
- **확인 완료**: 각자 Enter를 누르면 자기 열에 "✔ 확인 완료"가 표시된다. 하단에 `확인 완료 n / 인원`.
- **전원 확인 완료 → 같은 방 S2로 이동**, 모든 플레이어 스톡 3·배율 0%로 초기화. **[결정]**
- 재경기·나가기 버튼은 두지 않는다. 방을 떠나려면 S2에서 [나가기]를 쓴다. **[결정]**

통계 정의 **[제안]** (코멘트의 "몇 킬? 넉백 배율 기여?"를 구체화)
| 항목 | 정의 |
|---|---|
| 킬 | 상대가 장외될 때, 그 상대를 마지막으로 때린 플레이어에게 1킬. 마지막 피격자 없이 혼자 떨어지면 아무에게도 주지 않는다. |
| 준 배율 | 내 공격으로 상대 넉백 배율을 올린 양의 합계(%). 피해 기여를 나타낸다. |
| 남은 스톡 | 경기 종료 시 남은 스톡. 승자 외에는 0. |

공간이 남으면 "낙사 수(스톡을 잃은 횟수)"를 4번째 항목으로 둘 수 있다. 통계가 3~4줄을 넘지 않게 한다.

무승부 **[결정]**
- 마지막 생존자들이 동시에 마지막 스톡을 잃으면 무승부로 처리한다.
- 상단에 "무승부", 동시에 탈락한 플레이어들은 같은 공동 1위로 표시하고 왕관 대신 같은 색 테두리를 쓴다. **[제안]**

예외
| 상황 | 처리 |
|---|---|
| 결과 화면에서 참가자가 나감/끊김 | 그 열을 "나감"으로 바꾸고 확인 대상에서 뺀다. 남은 사람만 확인하면 S2로 간다. **[제안]** |
| 결과 화면에서 호스트가 끊김 | 참가자 전원 S1로, 토스트 "호스트와의 연결이 끊어졌습니다." |
| 누군가 계속 확인하지 않음 | 프로토타입에서는 자동 진행 없이 기다린다. 필요하면 일정 시간 뒤 자동 확인을 나중에 추가한다. **[미정]** |
| S2로 돌아갔는데 인원 1명 | S2 규칙대로 시작 버튼 비활성 |

## 8. 결정 사항

### 결정됨 (v2)

| # | 항목 | 결정 |
|---|---|---|
| 1 | 다른 컴퓨터 간 접속 | 지원한다 |
| 2 | 방 생성·참가 방식 | IP 직접 입력만 허용 |
| 3 | 경기 시작 권한 | 참가자 전원이 [준비 완료]를 누르면 호스트가 시작 |
| 4 | 최대 인원 | 프로토타입은 4명 |
| 5 | 경기 중 입장 | 난입 불가 |
| 6 | 재경기 | 스톡 3으로 초기화 (같은 방 S2로 복귀) |
| 7 | 동시 탈락 | 무승부 처리 |
| 8 | 재스폰 대기 시간 | 3초 |
| 9 | 시작 위치 | 플랫폼 위 랜덤 위치 |
| 10 | 결과 화면 | 플레이어별 순위 + 간단한 통계, 전원 Enter 확인 시 S2로 이동 |
| 12 | 일시정지 | 없음 |

### 남은 질문

1. **경기 상태를 확정하는 주체** (#11): 이 문서는 호스트 권한형(현재 코드 구조)으로 가정했다. 그래서 "호스트 끊김 = 경기 종료 후 S1"로 처리한다.
2. **경기 중 퇴장·끊김·재접속**: 난입 불가는 정해졌지만 나간 플레이어 처리는 아직이다. 이 문서는 "탈락 처리, 재접속 없음"으로 가정했다.
3. **통계 정의**: 킬을 "마지막으로 때린 사람"에게 주는지, 준 배율을 통계로 쓸지 확인이 필요하다.
4. **호스트의 준비 여부**: 호스트는 [경기 시작]이 곧 준비라고 가정했다. 호스트도 따로 준비를 눌러야 하는지 확인이 필요하다.
5. **S4에서 확인하지 않는 사람**: 자동 확인 시간 제한을 둘지.
6. **랜덤 시작 위치 간 최소 거리**: 시작하자마자 붙어 있지 않도록 최소 간격을 둘지.

## 9. 구현 순서 제안

1. S2 대기실: 기존 플레이스홀더를 슬롯 / 인원 / 준비 완료 / 시작 버튼 조건으로 확장
2. S3 HUD: 플레이어 카드(배율·스톡), 내 캐릭터 표시, 재스폰 3초 카운트다운, 무적 표시
3. S4 결과 화면: 플레이어별 순위 열 + 통계 + Enter 확인 → S2 복귀 (스톡 초기화)
4. 통계 수집: 마지막 공격자 기록(킬), 준 배율 누적
5. 연결 끊김 공통 처리 (S1 토스트로 귀결)
6. 카운트다운, 위험도 색, 화면 밖 화살표 같은 [제안] 연출
