## 0. 결론

문서 하나하나의 완성도는 높다. 상태 enum, 전이표, 노드 트리, 예외 매트릭스까지 갖춰서 화면 단위 명세로는 충분하다. 문제는 **문서 사이**에 있다.

1. **[확인] 02를 쓰면서 내린 결정이 00·01에 반영되지 않았다.** 해상도(1920×1080), 닉네임 길이(10자), 새 데이터(`MatchSetup`, `ContentCatalog`, 캐릭터·맵 필드)가 00에 없다. 02는 00의 없는 절(§3.6 `MatchSetup`, §3.8 `ContentCatalog`)을 참조한다.
2. **[확인] 00은 "`AI_GODOT_GUIDE.md`와 다르면 그 파일을 따른다"고 적었는데, 그 가이드는 1280×720, 루트 폴더 구조, Theme 리소스를 요구한다.** 코딩 AI가 이 규칙을 지키면 내려 둔 결정이 거꾸로 뒤집힌다.
3. **[확인] 화면 사이 이동 규칙(어느 화면의 어떤 결과가 어느 화면으로 가는가)을 적은 곳이 없다.** `ScreenRouter`의 함수 서명도 00과 01이 다르다.
4. **[확인] 1920×1080 전환은 UI만의 문제가 아니다.** `arena.gd`의 `screen_bounds`(1280×720)가 낙사 경계 계산에 쓰여서, 바꾸면 게임 규칙이 달라진다.
5. **[확인] 첫 구현 단계에 필요한 문서가 비어 있다.** SYS-01의 [뒤로가기]가 가는 메인 화면(SYS-00), 대기방에서 시작하면 가는 경기 화면, 결과 화면, 훈련장 치트 문서가 없다.

권장: 새 화면 문서를 더 쓰기 전에 **00을 v0.4로 올려 위 1~3을 정리**하고, 01·02는 00을 따르도록 짧게 고친다(반나절 분량 [추정]).

### 3.3 오디오

**[확인]** 저장소에 `AudioStreamPlayer`, `AudioServer`, 버스 레이아웃(`default_bus_layout.tres`)이 하나도 없다. 02의 배경음·효과음 슬라이더는 저장만 되고 아무 소리도 바꾸지 않는다. 슬라이더 값(0~100)을 어떤 버스에 어떤 공식(예: `linear_to_db(value / 100.0)`)으로 넣는지, 버스 이름(`Music`, `SFX`)을 00에 적어야 한다. 지금은 "값 저장만, 소리 적용은 사운드 작업 때"라고 명시하는 것도 방법이다.

## 6. 잘 된 점 (유지할 것)

- **[확인]** 모든 화면 문서가 같은 5단 구조(상태 → 데이터 → UI → 로직 → 예외)를 지킨다. UI와 로직을 나눈 덕분에 `_apply_state()` 한 곳에서만 표시를 바꾸는 구조가 자연스럽게 나온다.
- **[확인]** 01·02 모두 "현재 코드의 어떤 함수를 재사용하는지"를 정확히 짚었다. 01이 인용한 `cancel_join`, `parse_address`, `local_ipv4`, `_remember_address`, `JoinRejection`, `JOIN_TIMEOUT_MSEC`는 모두 `session.gd`에 실제로 있다.
- **[확인]** 연타, 같은 프레임 경쟁(취소와 성공), 조작된 RPC 같은 예외를 표로 다뤘다. 네트워크 게임 명세에서 가장 자주 빠지는 부분이다.
- **[확인]** 결정 기록을 문서 끝에 남겨서, 왜 그렇게 정했는지 다시 묻지 않아도 된다.
