# 장외·패배 규칙 구현

> 후속 전체 GDD 구현으로 실행 씬은 `main.tscn`으로 변경되었다.
> 최신 실행 방법·방향별 공격·플랫폼 충돌·네트워크 정책은 `implementation-status.md`를 따른다.

## 실행

Godot 4.7.2에서 프로젝트를 실행하면 `arena.tscn` 로컬 2인 검증 씬이 열린다.
기존 `control.tscn`은 보존했다. 네트워크 경기·메뉴 구현은 이 작업에 포함되지 않는다.

| 플레이어 | 이동 | 점프 | 공격 |
|---|---|---|---|
| P1 | A / D | W | J |
| P2 | ← / → | ↑ | K |

R은 경기 전체를 초기화한다. 스톡, 배율, 재스폰 대기, 무적, 공격·피격 상태를 초기화한다.
HUD에 각 플레이어의 스톡·배율·재스폰 대기·무적 시간과 결과를 표시한다.

## 조정 가능한 임시 값

원본 핸드오프의 미정 사항을 확정한 것은 아니다. 다음 값은 검증용 기본값이다.

| 설정 | 기본값 | 위치 |
|---|---|---|
| 화면 바깥 허용 거리 | 160px | resources/combat_rules.tres |
| 재스폰 대기 | 2초 | resources/combat_rules.tres |
| 넉백 증가 계수 | 1 | resources/combat_rules.tres |
| 배율 상한 | 0 = 무제한 | resources/combat_rules.tres |
| 기본 공격 배율 증가 | 12% | resources/basic_attack.tres |
| 기본 공격 피해 | 10 | resources/basic_attack.tres |
| 기본 공격 발사 속도 | 420px/s | resources/basic_attack.tres |
| 피격 입력 제한 | 0.35초 | resources/basic_attack.tres |

스톡 3개와 재스폰 무적 3초는 확정 규칙 상수다.
실제 발사 속도는 `기본 속도 × (1 + 증가한 배율 × 증가 계수 / 100)`다.
피해량과 배율 증가량은 별개이며 일반 HP 사망은 없다.

## 미정 항목에 적용한 임시 정책

- 화면 기준은 고정 1280×720 경기 좌표다. 창 크기 변경에도 동일한 경기 영역을 유지한다.
  캐릭터 중심이 좌·우·상·하 화면 경계에서 설정 거리 이상 벗어나면 장외다.
- 생존 → 재스폰 대기 또는 탈락으로 먼저 전환하므로 같은 장외 사건은 한 번만 차감한다.
- 장외 즉시 속도·피격·공격 예약·쿨다운·피해 누적을 초기화하고 숨긴다.
  탈락 오브젝트는 경기 내 보존하되 입력·피격·재참여를 차단한다.
- 재스폰 후보는 플랫폼 위면에 캐릭터 발이 닿는 위치다. 가장자리 여백과 다른 플레이어의
  점유 영역을 제외하고 후보 중 무작위 선택한다. 빈 후보가 없으면 대기 후 재시도한다.
- 무적은 `receive_hit`의 피해·배율·피격 상태·발사와 `apply_external_impulse`의 외부 힘을 모두 차단한다.
  본인 입력, 중력, 지형 충돌, 장외 판정은 계속 적용된다. 향후 환경 효과도 반드시 이 API를 사용해야 한다.
- 기본 공격은 바라보는 방향과 약간 위쪽으로 발사한다. 공격별 명시적 벡터를 피격 API에 전달한다.
  외부 공격도 방향을 전달해야 하며 0 벡터는 거부한다.
- 같은 프레임 공격은 먼저 적중 목록을 만들고 플레이어 순서대로 적용한다.
  배율은 모두 누적되며 마지막 적중의 발사 벡터로 속도가 교체된다.
- 같은 물리 프레임의 모든 장외를 처리한 다음 결과를 확정한다.
  스톡이 남은 플레이어 1명은 승리, 0명이면 무승부다. 종료 후 재스폰과 전투는 중단한다.
- 이동·점프·기본 공격·플랫폼은 검증용 최소 구현이다. 공격 종류, 아래 통과,
  플레이어 간 충돌, 네트워크 동기화 등 다른 핸드오프의 전체 구현은 별도 작업이다.

## 검증

Godot에서 다음 명령으로 회귀 검증한다.

```powershell
godot --headless --path . --script res://tests/combat_test.gd
```

초기 상태, 공격 방향과 누적 발사 속도, 네 방향 장외 경계, 중복 차감,
재스폰 대기와 플랫폼 접촉 위치 100회, 무적 차단과 만료, 탈락 후 재참여 차단,
승리와 동시 마지막 스톡 무승부를 검증한다.
